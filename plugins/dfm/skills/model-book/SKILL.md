# Книга DFM — контракт построения

Профиль по умолчанию — `dfm.full.v26`. Что такое профиль и когда книга
собирается иначе — `/dfm:model-profile`. Контроли и верификация —
`/dfm:model-audit`. Лист Dashboard — `/dfm:model-dashboard`.

Не применять к произвольным таблицам вне DFM.

---

## 1. Состав книги — 26 листов в фиксированном порядке

| Группа | Листы | Цвет вкладки |
|---|---|---|
| front | Cover, Business_Model, Timeline | `#1F3864` |
| input | Data_Input, Assumptions, Structure | `#2E75B6` |
| calc | Revenue, COGS, OPEX, Personnel, CAPEX, Working_Capital, Financing, Tax | `#548235` |
| report | P&L, Cash_Flow, Balance | `#404040` |
| analysis | KPI, Scenarios, Sensitivity, Dashboard | `#BF8F00` |
| control | Checks, Lineage | `#C00000` |
| tech | Export, _DFM_META (скрыт), DEV_LOG | `#808080` |

Шапка каждого листа: A1 = `DATA FIN MODEL — <имя>`, A2/B2 назначение,
A3/B3 группа, A4/B4 статус. Закреплено 5 строк.

`_DFM_META` скрывать **только на финальном шаге** — во время сборки он должен
быть виден для проверки.

**Done when:** коллекция листов книги содержит ровно эти имена в этом порядке,
пустых вкладок нет.

## 2. Раскладка расчётного листа — жёсткий контракт

| Строки | Содержание |
|---|---|
| 6 | заголовок `ПОДКЛЮЧЁННЫЕ ДОПУЩЕНИЯ` |
| 7–18 | подключённые допущения: A `assum_id`, B наименование, C ед.изм., D значение |
| 20 | метка периода `=Timeline!F$15` |
| 21 | `period_id` `=Timeline!F$12` |
| 22 | `flag_active` `=Timeline!F$21` |
| 23 | колонтитул: A `metric_id`, B Показатель, C Ед.изм., D Знак, E Источник |
| 24+ | показатели |
| F:AO | 36 периодов |

Допущение подтягивается **один раз** в столбец D:
`=INDEX(DFM_Assum_Active;MATCH("A_XXX";DFM_Assum_ID;0))` — зелёным.
Формулы периодов ссылаются на `$D7`…`$D18`. Не повторять `INDEX+MATCH`
в 36 столбцах.

**Done when:** формула первого периода протягивается вправо без правки
литералов; в строке нет ни одного числа-константы.

## 3. Structure — карта, а не второй движок

`Structure` объявляет иерархию статей и собирает их. **Считают профильные
листы.** Каждая статья несёт `source_sheet` и `source_row`; формула статьи —
прямая ссылка вида `=OPEX!F25`.

Раскладка: реестр `tblSTRUCT_Items` сверху; блок статей и блок групп ниже,
**разделены**. Группа = `SUM` непрерывного диапазона дочерних статей.
Пересечение диапазонов блоков даёт циклическую ссылку — не допускать.

Цепочка раскрытия обязана быть непрерывной:
`Dashboard` → `P&L` → `Structure` → расчётный лист.

**Done when:** для любой строки P&L можно за три перехода дойти до листа, где
число посчитано.

## 4. Формулы

Разрешено: `INDEX`, `MATCH`, `XLOOKUP`, `SUMIFS`, `COUNTIFS`, `SUMPRODUCT`,
`IFERROR`, `CHOOSE`, `EOMONTH`, `EDATE`, `ISFORMULA`, `FORMULATEXT`,
структурные ссылки.

Запрещено без согласования: VBA, макросы, внешние ссылки, `OFFSET`,
`INDIRECT`, `NOW`, `TODAY`, `RAND`.

- Дата обновления — статический штамп, не `TODAY()`.
- Сценарии — `INDEX`/`MATCH` по блоку Base/Optimistic/Pessimistic,
  не `INDIRECT`.
- Ни одного бизнес-числа внутри формулы. Делители и базы («дней в периоде»,
  «шаг ставки») — в отдельных помеченных ячейках.
- Логика не дублируется: величина считается в одном месте, остальные
  ссылаются.

## 5. Оформление и именование

Цвет шрифта: синий `#0000FF` вход · чёрный формула на листе · зелёный
`#008000` ссылка на другой лист · красный `#FF0000` внешняя ссылка
(запрещена). Жёлтая заливка `#FFFF00` — требует заполнения.

Форматы: суммы `#,##0;(#,##0);-`, проценты `0.0%;(0.0%);-`, множители
`0.0x;(0.0x);-`, даты `yyyy-mm-dd`, годы и номера блоков — текстом.

Имена: `DFM_<Лист>_<Показатель>`, таблицы `tbl<ЛИСТ>_<Сущность>`.

Excel Tables — только для вертикальных реестров. Расчётные листы с периодами
по столбцам — жёсткая сетка плюс именованные диапазоны.

## 6. Инструменты — проверенные ограничения

Эти пункты стоили отладки; они не выводятся из документации.

- `range.copyFrom` в Office.js **не тиражирует** шаблон на широкий диапазон и
  завершается без ошибки. Использовать инструмент копирования диапазонов.
- Не копировать диапазон сам на себя — очищает его.
- `range.numberFormat` требует массив либо 1×1, либо точно по размеру
  диапазона.
- `table.rows.add` может оставлять пустые строки-разрывы внутри таблицы —
  после добавления проверять и удалять.
- Новые строки таблицы не наследуют числовой формат — переустанавливать
  формат дат и текстовых колонок.
- Даты записывать серийным числом, не объектом `Date`.
- Структурные ссылки `[@Колонка]` падают на пустых таблицах — использовать
  прямые ссылки.

## 7. DEV_LOG

После каждого блока — записи в `tblDEVLOG_Entries`: `session`, `date`,
`block`, `action`, `sheets_touched`, `ranges`, `decision`, `assumption`,
`status`.

**Done when:** есть запись на каждый блок, включая принятые решения и
допущения.
