# Профиль стандарта

Полная спека: `docs/Профили_стандарта_и_выбор.md`. Практика построения книги
по профилю — в продуктовом плагине: `/dfm:model-profile` и `/dfm:model-book`.
Здесь — что делать на стороне разработки.

## Главное правило

**Единого стандарта нет и не будет.** Есть контракт и есть профили.

| Слой | Меняется |
|---|---|
| `assumptions.v1` — какие допущения и с какой семантикой | нет, контракт |
| Коды листов и именованные диапазоны (`RevenueRow`, `NetCFRow`, `NPV`, `DSCRmin`) | нет, контракт |
| Число листов, подписи, порядок, цвета, локаль, раскладка строк | **да, профиль** |

Внешний агент адресует модель по кодам и диапазонам. Всё остальное — оформление.

## Известные профили

| Профиль | Что это |
|---|---|
| `dfm.core.v1` | 15 листов, русские подписи — текущий `book/registry.py`. Безопасный минимум |
| `dfm.full.v26` | 26 листов, английские коды, лист `Structure`, жёсткая раскладка расчётного листа (строки 7–18 допущения, 20–23 шапка, F:AO периоды) |
| `bank.<name>.v1` | под требования конкретного банка |
| пользовательский | любой, если сохраняет обязательное ядро |

## Как выбирается — по приоритету, детерминированно

1. `standard_id` передан явно → берём.
2. Профиль воркспейса задан → берём. *(после auth)*
3. Из цели: заявка в банк → `bank.*`; инвестор → `dfm.full.v26`;
   контроллинг или экспорт → `dfm.core.v1`.
4. Отрасль сужает кандидатов.
5. Кандидатов больше одного → уточнить у пользователя.
6. Ничего не известно → `dfm.core.v1`, с явной пометкой «принято по умолчанию».

Шаг 6 обязателен: **никогда не блокировать работу вопросом.** Если ответа нет —
применить дефолт, записать допущение в provenance и сказать об этом в конце.

## Уточнение

Уточнение возвращается структурой, а не свободным текстом: вопрос, причина
(«от этого зависит состав листов»), варианты с полем `implies`, дефолт и флаг
`blocking`. Одна структура работает и для человека, и для внешнего агента.

Уточнять только то, что реально меняет результат. Формулировки пользователя не
переспрашивать.

## Чего не делать

- Не «приводить к единому стандарту» расхождение 15↔26 листов: это два
  легитимных профиля, а не ошибка.
- Не зашивать состав листов в код: состав — данные.
- Не менять коды листов и имена диапазонов ради красоты. Подпись менять можно,
  код — нет.
