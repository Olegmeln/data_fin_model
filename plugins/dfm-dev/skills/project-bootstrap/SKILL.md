# Протокол старта

Полная версия: `docs/Протокол_старта_проекта.md`. Здесь — исполняемая выжимка.

## Роли: не путать

| Артефакт | Кто |
|---|---|
| Репозиторий на GitHub, локальный клон, коммит, push | **пользователь** |
| Каталоги внутри репозитория, содержимое файлов, доки | **Claude** |

У Claude в облачном контейнере нет `gh` и нет push-кредов. Никогда не обещать
создать репозиторий и не просить об этом посреди работы — вопрос решается до
начала.

## Режим доставки

Сначала выяснить, подключена ли папка проекта (`get_device_info` →
`connectedFolders`).

- **Подключена** → писать файлы прямо в рабочую копию. Пользователь смотрит
  diff и коммитит в GitHub Desktop. Это режим по умолчанию: GitHub Desktop не
  умеет применять патчи.
- **Не подключена** → запросить доступ к папке. Отказ или недоступность
  машины → отдать патч `NNNN-описание.patch` для `git am` из `files\`.

Перед прямой записью проверить `git status`. Есть незакоммиченные изменения —
предупредить и **не трогать** эти файлы. Создавать новые пути безопасно всегда.

## Именование

- Репозиторий — `snake_case`: `data_fin_model`
- Плагин и скилл — `kebab-case`: `dfm-dev`, `project-bootstrap`
  (имя плагина становится namespace: `/dfm-dev:project-bootstrap`)
- Документ в `docs/` — русский, `_` вместо пробелов
- Патч — `NNNN-описание.patch`, сквозная нумерация по репозиторию
- Код в реестре — `snake_case` латиницей, **стабилен навсегда**: это контракт.
  Подпись, порядок, цвет, локаль — не контракт, их менять можно.

## Новый репозиторий или подкаталог

Новый репозиторий — только если **все три** «да»:

1. свои потребители помимо этого проекта;
2. свой цикл релиза и версия;
3. своя лицензия.

Иначе — подкаталог. Разделение откладывается бесплатно: маркетплейс умеет брать
плагин из подкаталога чужого репозитория источником `git-subdir`.

## Стартовый комплект — 8 пунктов

До первой строки кода:

1. `README.md` — что, для кого, как запустить. Не формулируется — проект не продуман.
2. `LICENSE` — решение **на старте**, не потом.
3. `.gitattributes` с `* text=auto eol=lf` — иначе на Windows весь репозиторий выглядит изменённым.
4. `.gitignore` и `.env.example`.
5. `docs/`: назначение и границы продукта + реестр инсайтов с условиями срабатывания.
6. Контракт и тест на него. Тест пишется на контракт, не на текущий список.
7. CI: прогон тестов на push.
8. Память Claude: `/projects/<id>/overview.md` и `ways-of-working.md`.

**Done when:** новая сессия по этим восьми файлам понимает, что делать, без вопросов.

## Старт подпроекта внутри репозитория

Пять пунктов: запись в `docs/` о цели и границе; каталог по правилам выше;
свой `README.md`, если есть точка входа; ответ «какой контракт добавляет» —
или явное «никакого»; строка в соответствующем реестре, если добавляет навык
или лист.
