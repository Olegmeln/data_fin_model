# Доставка изменений

## Выбор режима

```
get_device_info → connectedFolders содержит data_fin_model?
  да  → прямая запись
  нет → device_request_folder_access("~/data_fin_model")
          выдан  → прямая запись
          отказ  → патч
```

## Режим 1: прямая запись (по умолчанию)

1. `git status --short` и `git rev-parse --abbrev-ref HEAD` — убедиться, что
   ветка та и понятно, что уже изменено.
2. Новые файлы создавать свободно. Существующие править **только те, о которых
   договорились**; чужие незакоммиченные изменения не трогать и сказать о них.
3. Файлы с кириллицей писать через staging в контейнере + `device_commit_files`,
   не через heredoc в `device_bash` — heredoc ломает кодировку.
4. В конце — перечислить, что записано, и напомнить: коммит в GitHub Desktop.

Claude не коммитит и не пушит. Это делает пользователь.

## Режим 2: патч

```
git format-patch --stdout -1 > 00NN-описание.patch
```

Нумерация сквозная по репозиторию, 4 цифры. Пользователь кладёт в `files\`,
применяет `git am`. Каталоги создаются самим патчем — отдельный `mkdir` не нужен.

Проверить применимость до отправки: `git apply --check`.

## Ловушка CRLF

Репозиторий без `.gitattributes` на Windows показывает **все** файлы
изменёнными: git видит смену переводов строк. Признак — `git diff --stat`
даёт одинаковое число вставок и удалений, а `git diff --stat --ignore-all-space`
пусто.

Лечение — `.gitattributes` в корне:

```
* text=auto eol=lf
*.xlsx binary
*.xlsb binary
*.pdf  binary
*.docx binary
```

До того как он появится, не судить по `git status` о том, что реально изменено.

## Сигнал конца блока

Каждый блок работы заканчивается одной из трёх строк — без неё блок не закрыт:

- `Требуется push`
- `Требуется миграция`
- `Ничего не требуется`
