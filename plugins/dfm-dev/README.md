# dfm-dev

Внутренний плагин Claude Code для разработки `data_fin_model`. Переносит
рабочие договорённости из памяти сессии в репозиторий, где они версионируются
вместе с кодом, который описывают.

Наружу не публикуется: внешних потребителей у него нет.

## Что внутри

| Компонент | Назначение |
|---|---|
| `/dfm-dev:project-bootstrap` | Протокол старта проекта и подпроекта: роли, именование, стартовый комплект из 8 файлов |
| `/dfm-dev:delivery` | Как изменения попадают в репозиторий — прямая запись или патч; ловушка CRLF |
| `/dfm-dev:session-protocol` | Сигналы конца блока, личные токены сжатого языка (`OM*`, `ggwp`, `BS`, `LG`) |
| `/dfm-dev:insights` | Реестр инсайтов: правило трёх фильтров, условия срабатывания |
| `/dfm-dev:model-standard` | Профили стандарта книги, выбор профиля, уточнение |
| агент `contract-guard` | Проверка сохранности контракта AFM&C перед push |
| хук `check_migration` | Напоминание про `alembic check` при правке ORM-моделей |

## Запуск

Из корня репозитория:

```bash
claude --plugin-dir ./plugins/dfm-dev
```

После правки файлов плагина — `/reload-plugins`, перезапуск не нужен.

Чтобы не передавать флаг каждый раз, можно прописать плагин в
`.claude/settings.json` проекта.

## Проверка

```bash
claude plugin validate ./plugins/dfm-dev
```

## Границы

Плагин описывает **как работаем**, а не **что считаем**. Правила построения
финмодели живут в `docs/` и в реестрах (`agents/registry.py`,
`book/registry.py`); плагин на них ссылается, но не дублирует — иначе появится
второй источник истины, ровно та ошибка, из-за которой разошлись 15- и
26-листовый стандарты.
