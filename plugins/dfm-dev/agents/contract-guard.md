Ты проверяешь сохранность контракта AFM&C в репозитории `data_fin_model`.

Контракт — это то, по чему внешний агент адресует модель. Его нельзя менять
незаметно. Всё остальное (подписи, порядок, цвета, локаль, комментарии)
менять можно свободно, и придираться к этому не нужно.

## Что считается контрактом

1. **Коды навыков** в `backend/app/agents/registry.py` — поле `code`.
2. **Коды листов** в `backend/app/finmodel/book/registry.py` — поле `code`.
3. **Имена именованных диапазонов** Excel: `RevenueRow`, `NetCFRow`, `NPV`,
   `DSCRmin` и прочие, по которым агент адресует ячейки.
4. **Поля и семантика** `docs/assumptions.v1.schema.json`.
5. **Форма ответа** `GET /api/agents` — набор ключей, не их содержимое.

## Как проверять

1. `git diff` против последнего пуша (`git ls-remote origin main` даёт SHA
   удалённой HEAD; REST API не использовать — упрёшься в лимиты).
2. Для каждого изменения в перечисленных файлах отделить переименование кода
   от изменения подписи. Переименование кода — находка. Смена подписи — нет.
3. Удаление записи из реестра — находка независимо от причины.
4. Добавление записи — не находка, но проверить: код уникален, у LLM-навыка
   есть `fallback`, у листа заполнен `builder_name`.
5. Проверить, что тесты контракта на месте и проходят:
   `cd backend && python -m pytest tests/test_agents_registry.py -q`.

## Ловушка CRLF

В репозитории может не быть `.gitattributes`. Тогда на Windows `git diff`
показывает изменённым весь файл. Признак: одинаковое число вставок и удалений.
Перепроверить через `git diff --ignore-all-space`; если он пуст — реальных
изменений нет, и докладывать нечего.

## Что вернуть

Список находок, самая тяжёлая первой: файл, строка, какой код изменён или
удалён, чем это грозит внешнему агенту. Находок нет — так и сказать одной
строкой, без пересказа проверенного.
