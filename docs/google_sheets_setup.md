# Настройка синхронизации с Google Sheets

Интеграция позволяет выгрузить финмодель в Google-таблицу пользователя (`push`)
и вернуть правки ключевых входов обратно в модель (`pull`). Ниже — как получить
OAuth-ключи Google и подключить аккаунт.

Интеграция **опциональна**: без ключей приложение работает как прежде, а эндпоинты
Google отвечают «не настроено» (HTTP 503). Ключи в коде не хранятся — только в
переменных окружения (как `ANTHROPIC_API_KEY`).

## 1. Проект в Google Cloud

1. Откройте <https://console.cloud.google.com/> и создайте проект (или выберите
   существующий).
2. **APIs & Services → Library**: включите **Google Sheets API** и **Google Drive API**.

## 2. Экран согласия OAuth

1. **APIs & Services → OAuth consent screen**.
2. Тип **External**, заполните название приложения и контактную почту.
3. **Scopes**: добавлять вручную не обязательно — приложение запрашивает
   `.../auth/spreadsheets` и `.../auth/drive.file` при авторизации.
4. Пока приложение в статусе *Testing*, добавьте свою почту в **Test users**
   (иначе Google не пустит на этап согласия).

## 3. OAuth Client ID

1. **APIs & Services → Credentials → Create credentials → OAuth client ID**.
2. Тип приложения: **Web application**.
3. **Authorized redirect URIs** — добавьте адрес обратного вызова:
   - локально: `http://localhost:8000/api/google/callback`
   - на проде: `https://<ваш-домен>/api/google/callback`
4. Скопируйте **Client ID** и **Client secret**.

## 4. Переменные окружения

В `.env` (локально) или в переменных окружения деплоя:

```
GOOGLE_CLIENT_ID=<ваш client id>
GOOGLE_CLIENT_SECRET=<ваш client secret>
GOOGLE_REDIRECT_URI=http://localhost:8000/api/google/callback
```

`GOOGLE_REDIRECT_URI` должен **точно** совпадать с тем, что указан в Google Cloud
и с реальным адресом приложения. На Vercel задайте боевой адрес и добавьте его в
список redirect URI.

## 5. Подключение и использование

1. Проверка статуса: `GET /api/google/status` → `{"configured": true, "connected": false}`.
2. Откройте в браузере `GET /api/google/auth` — вас перенаправит на согласие Google;
   после подтверждения вернёт в приложение (`/?google=connected`).
3. Выгрузка модели: `POST /api/sheets/push?title=Моя%20модель` → вернёт `url`
   готовой Google-таблицы (полный формат: 7 листов, формулы, именованные диапазоны).
   Повторный `push` обновляет **ту же** таблицу — ссылка не меняется.
4. Правки обратно: измените входы на листе «Допущения» (выручка `B21`, ФОТ `B31`,
   аренда `B32`, CAPEX `B38`, сумма кредита `B42`, ставка кредита `B43`, ставка
   дисконтирования `B6`), затем `POST /api/sheets/pull` — значения вернутся в
   профиль и попадут в модель при следующей сборке.
5. Отключение: `POST /api/google/disconnect` удаляет сохранённые токены.

## Область доступа и хранение

- Запрашиваются минимальные scope: `spreadsheets` (чтение/запись таблиц) и
  `drive.file` (доступ только к файлам, созданным приложением, — не ко всему Диску).
- Токены хранятся в таблице `google_credentials`. Текущая реализация
  **single-tenant** (одна строка на инсталляцию) — полноценные пользователи и
  рабочие пространства запланированы отдельным пунктом дорожной карты.
- На бесплатном тарифе Vercel БД по умолчанию — эфемерный SQLite в `/tmp`, поэтому
  подключение обнулится между холодными стартами; для постоянного хранения токенов
  подключите Postgres (Neon), как описано в основном README.

## Ограничения первого среза

- Двусторонний цикл реализован на уровне **драйверов-входов** (перечислены выше),
  а не каждой ячейки модели. Остальные листы (Модель, Дашборд, Чувствительность)
  пересчитываются формулами в самой таблице.
- Живой раунд-трип к Google в CI не проверяется (нужны реальные ключи); логика
  push/pull, OAuth и обновления токена покрыта юнит-тестами с замоканным клиентом
  (`backend/tests/test_google_sheets.py`).
