# Продуктовая стратегия и реестр инсайтов

Правило: **один критический путь, всё остальное — в реестр с триггером.**
Инсайт, попавший в реестр, не потерян — он ждёт своего триггера. Инсайт,
не попавший в реестр, потерян. Поэтому реестр пополняется в конце каждой
рабочей сессии.

## Северная звезда (до тестирования и инвестраунда)

**Документ «переворачивается» в финмодель по нашей схеме.**

PDF / DOCX / XLSX / CSV / PPTX / Google Sheets
→ извлечение существенных данных с сохранением структуры и источников
→ допущения по схеме `assumptions.v1` (auto / AI / manual)
→ книга модели по нашему реестру листов
→ выгрузка Excel / Google Sheets.

Критический путь (порядок жёсткий, ничего между пунктами не вставляем):
1. Схема допущений (pydantic + БД, версионирование на проект)
2. Экстрактор документов (LLM, выход строго по схеме, каждый факт с источником)
3. Валидатор (арифметика, сверка документов между собой, список «требуют уточнения»)
4. Форма допущений в workspace v2 (auto/AI/manual) + память предпочтений
5. Генерация книги по sheet registry + экспорт
6. Тестирование на 3–5 реальных кейсах → материалы для раунда

Критерий «размениваемся на мелочи»: если задача не приближает ни один из
шести пунктов — она идёт в реестр, а не в работу.

## AFM&C как индустриальный стандарт (развитие мысли)

AFM&C — Automated Financial Modeling & Control: модель не как файл-артефакт,
а как воспроизводимый объект со стандартной схемой допущений, стандартной
структурой книги и контролем исполнения.

Аналогия — XBRL в финотчётности и IFC в строительстве: выиграл не лучший
редактор, а тот, чей формат стал обязательным языком обмена. Путь:

1. **Открытая спецификация.** Публикуем `assumptions.v1` и структуру книги
   как открытый стандарт (spec + JSON Schema + референсный валидатор).
   Открытость — условие принятия рынком; монетизация не в схеме, а в
   инструментах вокруг неё.
2. **Совместимость как знак качества.** «AFM-совместимая модель» = модель,
   которую банк может проверить автоматически за минуты вместо недель
   кредитного анализа. Первый банк, принявший формат, экономит на экспертизе —
   это и есть канал внедрения стандарта (заходим через И-1).
3. **Сетевой эффект.** Заёмщики подают AFM-модели, потому что их быстрее
   рассматривают; банки требуют AFM, потому что дешевле проверять;
   консультанты выпускают AFM, потому что этого требуют обе стороны.
4. **Монетизация вокруг стандарта:** SaaS-конструктор (наш продукт) —
   для заёмщиков и консультантов; аудит/скоринг API — для банков;
   сертификация и маркетплейс отраслевых шаблонов — позже. Контроль
   исполнения (И-2) превращает разовую продажу в подписку: модель живёт
   после выдачи кредита как инструмент мониторинга ковенант.
5. **Защита позиции.** Стандарт копируется, экосистема — нет: библиотека
   отраслевых профилей по умолчанию, память предпочтений, база требований
   банков и накопленные кейсы аудита остаются нашими.

Практический шаг нулевой стоимости уже сейчас: вести `assumptions.v1`
и sheet registry так, как будто они публичные — чистые имена, версии,
changelog. Тогда «открыть стандарт» в нужный момент — операция на день.

## Порядок работы с реестром

В конце сессии: новые инсайты → в таблицу. Начало сессии: проверить,
не сработали ли триггеры. Изменение критического пути — только осознанным
решением с записью причины здесь же.
