## 1. Принцип: модель — не шаблон, а сборка

Одна форма на всех не работает: инвестиционная идея на салфетке и проектное
финансирование стройки требуют разной глубины, разных листов и разной подачи.

Поэтому: **состав книги вычисляется** из конфигурации проекта (§2), а не
выбирается из готовых шаблонов. Реестр листов уже data-driven — добавляем
предикаты включения и параметры детализации.

---

## 2. Типология: когда и какая модель нужна

Три независимых измерения. Их комбинация и даёт конфигурацию.

### 2.1. Тип объекта моделирования

| Код | Тип | Суть | Что добавляет в книгу |
|---|---|---|---|
| `operating` | Действующий бизнес | Факт первичен, прогноз — продолжение тренда | План-факт, история, бюджет на период |
| `greenfield` | Новый проект с нуля | Допущения первичны, есть инвестфаза | CAPEX-график, runway, ramp-up |
| `expansion` | Действующий + инвестпроект | Два контура: база as-is и приростный проект | Консолидация «база + проект», приростный CF, оценка проекта отдельно от компании |
| `tree` | Проект из подпроектов | Стройка → производство → реализация | Дерево подпроектов, свои графики, консолидация (§3) |
| `group` | Группа компаний / холдинг | Несколько юрлиц | Консолидация, внутригрупповые обороты и их элиминация, матрица владения |
| `idea` | Инвестиционная идея | Данных почти нет, всё — допущения | Упрощённая книга, диапазоны вместо точек, явная пометка «предварительно» |
| `refinance` | Рефинансирование / реструктуризация | Существующий долг → новый | График старого и нового долга, сравнение сценариев |
| `valuation` | Оценка бизнеса / M&A | Стоимость, а не поток | DCF, терминальная стоимость, мультипликаторы |

Список открытый: новый тип = запись в реестре + предикаты листов.

### 2.2. Цель (кому показываем)

Уже описана в `Конфигурация_модели_и_конвейер.md` §1.2: банковское
финансирование · инвестор/раунд · анализ решения · запуск · мониторинг.
Дополнить: **господдержка/субсидии** (ФРП, гранты — свои формы и требования),
**внутренний бюджет** (без внешнего читателя, зато с план-фактом).

### 2.3. Глубина проработки

Новое измерение. Определяет требуемую точность и объём книги:

| Уровень | Что известно | Поведение продукта |
|---|---|---|
| Идея | Замысел, порядок цифр | Диапазоны, бенчмарки отрасли, короткая книга, дисклеймер |
| Пред-ТЭО | Есть КП, прикидки, аналоги | Базовая книга, много допущений, карта пробелов на первом плане |
| ТЭО / проект | Сметы, КП, договоры | Полная книга, допущения вытесняются документами |
| Реализация | Идёт стройка/закупки | План-факт по инвестфазе, контроль бюджета |
| Эксплуатация | Есть выручка и выписки | Полный контур C: факт вытесняет прогноз, ковенанты, алерты |

Глубина не задаётся вручную — **выводится агентом** из состава загруженных
документов и заполненности карты полноты, но может быть переопределена.

## 3. Дерево проекта: подпроекты и консолидация

Ключевое обобщение, закрывающее «стройка + производство», группу компаний и
мультипродуктовые проекты одним механизмом.

**Проект = узел дерева.** У каждого узла: свой тип (§2.1), свой календарь,
свои допущения, свои расчётные листы. Родитель консолидирует детей.

```
Проект «Агрокомплекс»                 tree
├── Подпроект «Строительство»         greenfield  мес 0–18   CAPEX, подрядчики
├── Подпроект «Производство»          greenfield  мес 12–60  сырьё, ФОТ, выпуск
└── Подпроект «Сбыт и логистика»      greenfield  мес 15–60  каналы, отсрочки
```

Правила:

- перекрытие фаз допустимо и нормально (сбыт стартует до конца стройки);
- межпроектные связи задаются явно: «выпуск подпроекта B — вход подпроекта C»,
  «CAPEX B финансируется траншем из A»;
- консолидация — сумма с элиминацией внутренних оборотов (для `group` — обязательна);
- метрики считаются на каждом узле и на корне: инвестор смотрит корень, банк —
  часто конкретный подпроект под свой транш;
- дорожная карта строится по дереву: вехи каждого узла на общей шкале (§6.4).

Схема: раздел `subprojects` в `assumptions.v1`, рекурсивно тот же тип, что и
корень. Совместимо: модель без подпроектов — дерево из одного узла.

## 4. Конфигуратор состава книги

На входе: тип объекта × цель × отрасль × глубина проработки × наличие данных.
На выходе: список листов с уровнем детализации.

Каждый лист в реестре получает:

- `predicate` — при каких конфигурациях включается;
- `detail` — уровень детализации (сводно / по статьям / по позициям);
- `owner` — какой подпроект (для дерева листы могут дублироваться по узлам).

Пример: «Расчёт амортизации» включается, если есть CAPEX; детализация
«по объектам ОС» — при глубине ТЭО и выше, иначе «сводно по группам».

## 5. Состав книги v2

Ниже целевой набор. Названия и группировка — рабочие, меняются при сборке.

### 5.1. Уровень представления (для чтения)

1. **Дашборд** — панель показателей проекта и макро (§6.1).
2. **Титульный лист** — сводный план: все ключевые показатели, коэффициенты,
   ковенанты, срезы данных, сценарные ползунки (§6.2).
3. **Бизнес-план** — текстовая часть с пояснением допущений (§6.3).
4. **Дорожная карта** — вехи по всему дереву проекта (§6.4).

### 5.2. Ядро расчёта

5. **Допущения** — единый слой (assumptions.v1), сгруппированный по разделам.
6. **Сводный денежный поток** — центральный лист: операционная, инвестиционная
   и финансовая деятельность в одной структуре, помесячно и с годовыми итогами.
   Собирается ссылками из расчётных листов, ничего не считает сам.

### 5.3. Расчётные листы — операционная деятельность

7. **План продаж** — по продуктам/каналам: объём × цена, сезонность, ramp-up,
   скидки, возвраты. Для `group`/`tree` — с разбивкой по узлам.
8. **Расходы на продажу** — комиссии, логистика сбыта, маркетинг, эквайринг,
   упаковка; привязка к объёму или к выручке.
9. **Производство / закупки** — себестоимость, нормы расхода, загрузка мощностей,
   брак, сезонность закупок.
10. **План товарных запасов** — остатки, оборачиваемость, страховой запас,
    опережающие закупки; связь с ДДС через изменение запасов.
11. **Штатное расписание и ФОТ** — план набора по периодам, оклады, премии,
    индексация, страховые взносы, НДФЛ; разбивка по подразделениям и подпроектам.
12. **Операционные и управленческие расходы** — аренда, ИТ, связь, НИОКР,
    прочие; фикс/переменная часть.

### 5.4. Расчётные листы — инвестиции и активы

13. **CAPEX и график ввода** — позиции, сроки, авансы, подрядчики, резерв.
14. **Основные средства и амортизация** — по объектам/группам: ввод, срок,
    метод, остаточная стоимость; ремонты и модернизация; выбытие.
15. **Оборотный капитал** — дебиторка, кредиторка, авансы: среднеотраслевые
    значения по умолчанию, переопределяются пользователем (§5.6).

### 5.5. Финансирование и налоги

16. **Финансирование** — собственные средства, транши кредитов, графики выборки
    и погашения, проценты, комиссии, ковенанты.
17. **Налоги** — агрегированный расчёт всех налогов по периодам: НДС
    (начисленный, к вычету, к уплате, возмещение с лагом), налог на прибыль,
    имущество, земля, страховые взносы, НДФЛ, спецрежимы; все ставки
    расписаниями во времени. Режим налогообложения подбирается по критериям
    и сравнивается с альтернативами — см. §11.2.

### 5.6. Прогнозная отчётность

18. **Прибыли и убытки (ПиУ)** — по методу начисления.
19. **Движение денежных средств (ДДС)** — прямой метод; по умолчанию совпадает
    с ПиУ, расходится ровно на величину оборотного капитала (дебиторка,
    кредиторка, запасы, авансы) — это делает связку прозрачной и проверяемой.
20. **Баланс** — активы = пассивы, со строкой контроля.

### 5.7. Анализ

21. **Сценарии** — пессимистичный / базовый / оптимистичный как параметры,
    сравнение в одной таблице.
22. **Чувствительность** — матрицы по ключевым драйверам.
23. **Ковенанты** — DSCR, ICR, LLCR, Долг/EBITDA против порогов, по периодам.

## 6. Ключевые экраны

### 6.1. Дашборд

Главная страница приложения. Два состояния:

- **проект загружен** — показатели проекта + макро страны (ключевая ставка,
  инфляция, курс) с датой среза;
- **проекта нет** — усреднённая картина «типового бизнеса» выбранной отрасли и
  страны: структура выручки и затрат, типовые маржи, сроки окупаемости. Это и
  демонстрация продукта, и точка входа: «похоже на ваш бизнес? — начать отсюда».

### 6.2. Титульный лист — панель управления

Не обложка, а рабочий экран:

- сводка всех ключевых показателей: NPV, IRR, MIRR, окупаемость (простая и
  дисконтированная), DSCR/LLCR, EBITDA-маржа, рентабельность, точка
  безубыточности, потребность в финансировании;
- коэффициенты: ликвидность, оборачиваемость, долговая нагрузка, автономия;
- срезы данных: по годам, по подпроектам, по продуктам, по каналам;
- блоки можно скрывать и добавлять (конфигурация видимости сохраняется);
- **сценарные ползунки**: цена, объём, CAPEX, ставка, сроки — двигаешь и
  показатели пересчитываются на глазах; на шкале отметки трёх сценариев.

### 6.3. Бизнес-план

Формируется командой пользователя **после** сохранения модели (модель — источник
цифр, текст не выдумывает числа). Краткий, но полезный:

- резюме проекта и запрос (сколько нужно, на что, под что);
- продукт, рынок, конкуренты, команда;
- **пояснения по допущениям** — почему такая цена, откуда норма расхода, на чём
  основан прогноз спроса; каждое существенное допущение со ссылкой на источник
  (документ или бенчмарк) и пометкой факт/допущение;
- инвестиции, финансирование, экономика проекта;
- риски и чувствительность;
- дорожная карта.

Экспорт: DOCX и PDF; для инвестора — вариант «живая ссылка» (премиум-модуль).

### 6.4. Дорожная карта

Единая шкала времени со всеми узлами дерева: фазы подпроектов, вехи CAPEX,
запуск продаж, выборка и погашение траншей, точка выхода в плюс, контрольные
события для банка. Разворот: свернуть до уровня подпроектов или раскрыть до
отдельных вех.

## 7. Интерфейс

### 7.1. Вкладки = листы модели

Отказ от абстракций «Обзор / Модель / Допущения». Верхний уровень — **реальные
листы книги**, как в Excel: Дашборд · Титульный · План продаж · ФОТ · CAPEX ·
Налоги · ПиУ · ДДС · Баланс · … Состав вкладок определяется конфигурацией (§4),
поэтому у розницы и у стройки он разный.

Плюс: пользователь видит ту же структуру в приложении и в выгруженном файле —
не нужно догадываться, где что.

### 7.2. Три пути ввода данных, один результат

1. **Промт** — описал словами, агент разложил на смыслы и заполнил.
2. **Документы** — загрузил, агент извлёк.
3. **Руками прямо в листе** — как в таблице; после подтверждения модель
   пересчитывается.

Любой ввод пишется в один слой допущений; происхождение сохраняется.

### 7.3. Цветовая семантика (возвращаем)

| Цвет | Значение | Поведение |
|---|---|---|
| Зелёный | Ввёл или подтвердил пользователь | Приоритет над всем; не перезаписывается агентом |
| Жёлтый | Заполнило приложение — допущение, бенчмарк, ИИ-извлечение | Кандидат на подтверждение; вытесняется фактом и правкой |
| Красный | Противоречие, нарушение, требует внимания | Расхождение документов, нарушенный ковенант, баланс не сходится |
| Серый / чёрный | Расчёт по формуле | Не редактируется напрямую |
| Синий | Факт из подключённого источника (выписка, 1С, банк API) | Не редактируется, вытесняет допущение |

Легенда на каждом листе. Цвет дублируется иконкой и текстом статуса
(требование доступности из дизайн-спеки).

## 8. Документы на входе: три канала

| Канал | Что попадает | Что делает продукт |
|---|---|---|
| **Факт** | Банковская выписка, обороты по счетам, архив 1С, отчётность | Строит текущую финансовую модель по факту и продолжает её прогнозом; факт вытесняет допущения |
| **Промт** | Задача, параметры прогноза, допущения, продукты, ограничения — свободным текстом или голосом | Раскладывает на смыслы: тип проекта, отрасль, продукты, драйверы; заполняет стартовый профиль |
| **Проектные документы** | Бизнес-план, КП, сметы, feasibility study, готовая финмодель, договоры, произвольные файлы | Извлекает допущения с источниками, сверяет между собой, формирует список противоречий и пробелов |

Стартовый профиль (когда ничего не загружено) — это схема типового бизнеса из
дашборда (§6.1), а не пустая форма.

## 11. Принятые решения (27.07.2026)

### 11.1. Периодичность: год как основа, месяц как глубина

- **Движок считает помесячно** — иначе не поймать кассовые разрывы, выборку
  траншей и ковенанты внутри года.
- **Представление по умолчанию — годовое.** Пользователь видит компактную
  таблицу по годам и может «провалиться» в квартал и месяц по любой строке
  (drill-down), не переключая режим всей книги.
- **Горизонт задаётся в годах, по умолчанию 3** (сейчас в схеме 5 — поменять).
  Для стройки и проектного финансирования пользователь ставит больше.
- В Excel-книге: годовые колонки на титульном и в отчётности, помесячные —
  на расчётных листах и в сводном CF; группировка колонок Excel даёт то же
  сворачивание, что и в интерфейсе.

Следствие для движка: ряды остаются месячными, добавляется слой агрегации
`aggregate(series, level)` и уровень отображения в конфигурации листа.

### 11.2. Налоги: полный расчёт + агрегированный лист

- **НДС считается полностью**: начисленный с реализации, к вычету (по CAPEX,
  закупкам, услугам), к уплате, возмещение из бюджета с лагом. Для стройки и
  производства возмещение НДС с CAPEX — существенный денежный поток.
- **Отдельный лист «Налоги»** — агрегированный расчёт всех налогов по периодам:
  НДС, налог на прибыль, имущество, земля, страховые взносы, НДФЛ, спецрежимы;
  все ставки расписаниями во времени.
- **Режим налогообложения выбирается по критериям**, а не просто спрашивается:
  агент оценивает выручку (лимиты УСН), долю расходов в выручке (порог
  выгодности УСН 15% против 6%), наличие НДС-контрагентов и потребность в
  возмещении НДС с CAPEX — и предлагает режим с обоснованием; пользователь
  подтверждает или меняет. Это же обоснование попадает в бизнес-план.
- Сравнение режимов — полезный побочный продукт: показать налоговую нагрузку
  при ОСНО / УСН 6% / УСН 15% на одних и тех же допущениях.
