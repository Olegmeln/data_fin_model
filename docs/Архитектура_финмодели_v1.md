# Архитектура книги финансовой модели — v1

Статус: рабочая спека. Итоговая версия будет содержать больше листов; стартуем с универсальной, настраиваемой (auto / AI / manual) формы из приложения с выгрузкой в Excel / Google Sheets.

## Ключевые принципы

1. **Универсальная настраиваемая форма.** Пользователь собирает модель в приложении; каждый лист — конфигурируемый модуль (включён/выключен, параметры). Режимы заполнения: auto (демо/данные), AI (агент предлагает), manual.
2. **Память предпочтений.** Если пользователь вносит изменения в приложении, они запоминаются и предлагаются по умолчанию в аналогичных задачах. Оценку «аналогичности» задачи выполняет агент (профиль проекта: отрасль, тип потоков, валюта, горизонт).
3. **Единый слой допущений.** Все листы читают параметры только из листа «Допущения» — единый источник истины, никаких «зашитых» констант в расчётных листах.
4. **Экспорт.** Excel (формулы живые, не значения) и Google Sheets.

## Состав книги (порядок листов)

1. **Обложка** — краткий бизнес-план (эссенция: продукт, рынок, команда, запрос).
2. **Дорожная карта проекта** — этапы, вехи, привязка к CAPEX и запуску продаж.
3. **Дашборд** — описание проекта; итоговые показатели (NPV, MIRR, срок окупаемости, DSCR и др.); коэффициенты; диаграммы; внизу — ползунки сценарного анализа с разметкой и отметками трёх сценариев (пессимистичный / базовый / оптимистичный).
4. **Развёрнутый дашборд** — опция, в будущих версиях.
5. **Допущения** — параметры по умолчанию (см. ниже), всё настраиваемо.
6. **Финансовая модель (сводный CF)** — общий лист всех денежных потоков: операционный (выручка, расходы), инвестиционный, финансовая деятельность — структурно и подробно. Центральный лист книги.

### Расчётные листы (по одному под каждый поток)

7. План продаж и расходов на продажу
8. План производства / закупки, хранение, логистика
9. Управленческие расходы и НИОКР
10. CAPEX, расходы на запуск, амортизация
11. ФОТ: план набора и расходы на персонал
12. Балансы, ПиУ (P&L), Налоги
13. Кредит и ковенанты

Сводный CF (лист 6) собирается ссылками из листов 7–13; дашборд (лист 3) — только из сводного CF и допущений.

## Допущения по умолчанию

- Профиль проекта: строительство → производство → реализация.
- Продуктовая линейка: 4 продукта = 2 товара + 2 услуги.
- Горизонт: 5 лет.
- Ставка дисконтирования: 9%.
- MIRR: корректируется на доходность (ROA) реинвестированных внутри модели средств.
- Ставки заимствования: 17% в рублях, 8% в долларах/евро.
- Структура финансирования: 30/70 собственные/заёмные (настраиваемо).
- Прочие коэффициенты и ковенанты — предустановленные значения по умолчанию, редактируемые.

## Сценарный анализ

Три именованных сценария (песс./база/опт.) заданы в допущениях. Ползунки на дашборде двигают ключевые драйверы (цена, объём, CAPEX, ставка и т.п.); на шкалах ползунков — отметки положений трёх сценариев. Механика совместима с уже реализованным сценарным движком Excel-экспорта.

## Следствия для разработки

- **Builder должен быть data-driven:** реестр листов (sheet registry) + конфиг книги, а не жёстко зашитая последовательность. Добавление листов в будущем — через реестр.
- **Слой допущений** выделить в отдельную модель данных (assumptions schema) с версиями и профилями по умолчанию.
- **Память предпочтений** — отдельная сущность: (профиль задачи → переопределённые параметры), агент подбирает ближайший профиль при создании новой модели.
- Тесты builder'а писать сразу на структуру реестра, а не на конкретный набор листов.
